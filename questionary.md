| **Java** | |
| Что такое переопределение метода? | Предоставление классом-наследником собственной реализации метода, уже объявленного в родительском классе. |
| Какие бывают виды классов? | Обычные — можно создавать экземпляры. Абстрактные — содержат неполную реализацию, экземпляры не создаются. Интерфейсы — чисто абстрактный контракт. Финальные — запрещено наследование. Перечисления (enum) — фиксированный набор констант. Записи (record) — неизменяемый носитель данных. Вложенные классы: статические, внутренние, локальные, анонимные. |
| Как и зачем можно использовать модификатор `final`? | final-класс — запрещает наследование (например, String). final-метод — запрещает переопределение в подклассах. final-переменная — присваивается ровно один раз. |
| Какие есть варианты использования ключевого слова `try`? | try-catch-finally — перехват исключений с обязательным блоком finally для освобождения ресурсов. try-with-resources автоматически вызывает close() у объектов, реализующих AutoCloseable. |
| Какие есть стандартные реализации интерфейса `List` и в каких ситуациях их нужно использовать? | ArrayList — динамический массив. LinkedList — связный список. В большинстве случаев лучше использовать ArrayList. LinkedList стоит использовать если есть частые вставки/удаления в середине или используется как Deque. |
| В чём основная идея стримов из пакета `java.util.stream`? | Декларативная обработка последовательностей данных в функциональном стиле. |
| **Разное** | |
| Каким критериям должна удовлетворять «хорошая» хэш-функция? | Детерминированность, равномерность распределения, лавинный эффект, быстрота вычисления. Для криптографических функций дополнительно устойчивость к коллизиям и необратимость. |
| В чём причина популярности и широкого распространения кодировки UTF-8? | Обратная совместимость с ASCII, отсутствие проблем с порядком байт (BOM не нужен). Широкая поддержка в ОС, протоколах (HTTP, JSON, XML) и языках программирования. |
| Сравните форматы XML и JSON. Когда какой использовать? | JSON — компактный, читаемый, стандарт в REST API. XML — многословный, но поддерживает работу со сложными документами и метаданными, используется в SOAP. |
| Опишите что будет происходить «под капотом» после ввода адреса сайта в браузере и нажатия Enter? | 1. DNS-разрешение — получение IP-адреса. 2. TCP-соединение с сервером. 3. TLS-рукопожатие (для HTTPS): обмен сертификатами, согласование шифра, установка защищённого канала. 4. HTTP-запрос. 5. Обработка на сервере — формируется ответ. 6. HTTP-ответ. 7. Отображение полученной страницы (HTML, CSS, прочее), либо стандартной страницы с кодом ошибки. |
